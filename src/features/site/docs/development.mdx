# Development

This guide covers the day-to-day development workflow for building features with
Takeout, from starting the dev server to running tests and debugging.

## Development Workflow

### Starting Development

The typical development workflow requires two terminal windows:

**Terminal 1: Backend Services**

```bash
bun backend
```

This starts Docker Compose with:

- PostgreSQL (port 5433)
- MinIO for S3-compatible storage (port 9200)
- Adminer database UI (port 8080)

**Terminal 2: Development Server**

```bash
bun dev
```

This starts:

- One.js development server (port 8081)
- Hot module reloading
- Type checking (optional, with `bun watch`)
- Zero codegen (optional, with `bun watch`)

Your app is now running at `http://localhost:8081`.

### Watch Mode

For a better development experience, run watch mode for automatic type checking
and Zero codegen:

```bash
bun watch
```

This runs in parallel:

- TypeScript type checking (`bun watch:types`)
- Zero code generation (`bun watch:zero:generate`)

## Hot Reloading

Takeout supports fast refresh on all platforms:

### Web

Changes to code automatically reload in the browser with state preservation:

- React components hot reload
- API routes restart automatically
- CSS updates instantly

### Native (iOS/Android)

Fast refresh works on mobile with some caveats:

- Component changes hot reload
- New dependencies require rebuild
- Native module changes need full rebuild

```bash
# iOS development
bun ios

# Android development
bun android
```

### Troubleshooting Hot Reload

If hot reload stops working:

```bash
# Clear cache and restart
rm -rf node_modules/.vite
bun dev
```

## Docker Compose Backend

### Starting Services

```bash
bun backend
```

### Stopping Services

```bash
# Stop services (keeps data)
docker compose down

# Stop and remove volumes (clean slate)
bun backend:clean
```

### Accessing Services

**PostgreSQL**

- Connection: `postgresql://user:password@127.0.0.1:5433/postgres`
- Use TablePlus, pgAdmin, or any PostgreSQL client

**Adminer (Database UI)**

- URL: `http://localhost:8080`
- System: PostgreSQL
- Server: `postgres`
- Username: `user`
- Password: `password`
- Database: `postgres`

**MinIO (S3 Storage)**

- Console: `http://localhost:9200`
- Access Key: `minio`
- Secret Key: `minio_password`

### Viewing Logs

```bash
# All services
docker compose logs -f

# Specific service
docker compose logs -f postgres
```

## Database Development

### Migrations

Takeout uses Drizzle ORM for type-safe database operations.

**Making Schema Changes**

1. Edit schema files:
   - `src/database/schema-public.ts` - Tables synced to client
   - `src/database/schema-private.ts` - Server-only tables

2. Generate migration (if backend is not running):

```bash
bun tko db generate
```

3. Run migration:

```bash
bun migrate
```

The migration runs automatically when `bun backend` is running.

**Custom Migrations**

For complex migrations outside Drizzle's capabilities:

```bash
bun db:migrate-add migration-name
```

Edit the generated file in `src/database/migrations/`.

**Important:** Takeout doesn't use down migrations. Only create migrations that
can be applied forward.

### Resetting Database

```bash
# Stop backend, remove data, and restart
bun backend:clean
bun backend
bun migrate
```

## Zero Development

### Generating Zero Code

Zero queries and mutations require code generation:

```bash
# One-time generation
bun tko zero generate

# Watch mode (recommended)
bun watch:zero:generate
```

This generates TypeScript types from your Zero schemas and queries.

### Zero Queries

Write queries in feature directories:

```typescript
// src/features/posts/queries.ts
export const postsQueries = {
  all: () => z.posts.orderBy('createdAt', 'desc'),
  byId: (id: string) => z.posts.where('id', id),
}
```

Use in components:

```typescript
import { useQuery } from '~/zero'
import { postsQueries } from './queries'

export function PostsList() {
  const [posts] = useQuery(postsQueries.all())

  return posts.map(post => <PostCard key={post.id} post={post} />)
}
```

See [Guides: Queries](/docs/guides-queries) for more details.

### Zero Mutations

Create mutations with optimistic updates:

```typescript
// src/features/posts/mutations.ts
export const createPost = mutation({
  name: 'createPost',
  async mutate(ctx, { title, content }: CreatePostInput) {
    const id = randomId()
    const post = {
      id,
      title,
      content,
      createdAt: Date.now(),
      userId: ctx.auth.userId,
    }

    await ctx.zero.posts.insert(post)
    return post
  },
})
```

See [Guides: Mutations](/docs/guides-mutations) for more details.

## Code Quality

### Linting

Takeout uses Biome for fast linting:

```bash
# Check for issues
bun lint

# Auto-fix issues
bun lint:fix
```

Configure Biome in `biome.json`.

### Type Checking

Run TypeScript type checking:

```bash
# One-time check
bun tko check types

# Watch mode
bun watch:types
```

### Full Check Suite

Run all checks before committing:

```bash
bun tko check
```

This runs:

- TypeScript type checking
- Biome linting
- Circular dependency detection

**Best Practice:** Always run `bun lint:fix && bun tko check types` after making
changes.

## Testing

### Unit Tests

Takeout uses Vitest for unit testing:

```bash
# Run all unit tests
bun test:unit

# Run in watch mode
bun test:unit --watch

# Run specific test file
bun test:unit src/features/auth/auth.test.ts
```

### Integration Tests

Playwright provides end-to-end testing:

```bash
# Run integration tests
bun test:integration

# Run in headed mode (see browser)
bun test:integration --headed

# Run specific test
bun test:integration tests/auth.spec.ts
```

### Running All Tests

```bash
bun test
```

## Debugging

### Client-Side Debugging

**Browser DevTools**

- React DevTools extension
- Zero DevTools (if available)
- Network tab for API calls

**Debug Logging**

```typescript
import { logger } from '~/features/logger'

logger.info('User logged in', { userId })
logger.error('Failed to fetch', { error })
```

### Server-Side Debugging

**Console Logging**

Use `console.info()` instead of `console.log()`:

```typescript
console.info('Server started', { port: 8081 })
```

**Node Inspector**

Debug server code with Node inspector:

```bash
bun --inspect dev
```

Then open `chrome://inspect` in Chrome.

### Database Debugging

**View Queries**

PostgreSQL logs slow queries automatically (>1000ms).

View logs:

```bash
docker compose logs -f postgres | grep duration
```

**SQL Client**

Use TablePlus or Adminer to:

- Inspect table data
- Run raw SQL queries
- View query plans with `EXPLAIN ANALYZE`

### Zero Debugging

**View Zero State**

Access Zero's internal state in dev:

```typescript
import { devGlobal } from '~/helpers/dev'

// In browser console
devGlobal.zero.dump()
```

**Zero Server Logs**

View Zero server logs for replication issues:

```bash
# Production
bun tko aws logs zero

# Development
docker compose logs -f zero
```

## Environment Management

### Environment Files

- `.env.development` - Default development config (committed)
- `.env` - Active environment (generated, gitignored)
- `.env.local` - Local overrides (gitignored)

### Adding Environment Variables

1. Add to `package.json` `env` section:

```json
{
  "env": {
    "NEW_VARIABLE": true
  }
}
```

2. Run update script:

```bash
bun env:update
```

3. Add example to `.env.development`:

```bash
NEW_VARIABLE=example-value
```

**Never** edit `src/server/env-server.ts` directly - it's auto-generated.

### Pulling Production Environment

Pull environment variables from production for debugging:

```bash
bun env:pull
```

## Development Tools

### REPL

Launch a REPL with app context:

```bash
bun repl
```

Access app internals interactively.

### Tunneling to SST

Test local code against production services:

```bash
bun dev-tunnel
```

This creates a tunnel to your SST infrastructure, useful for testing:

- OAuth callbacks
- Webhooks
- Mobile app development

### Font Subsetting

Reduce bundle size by subsetting fonts:

```bash
bun tko subset-fonts
```

This extracts only used characters from font files.

## Best Practices

### Code Style

- Use `~` alias for non-relative imports
- Prefer `console.info()` over `console.log()`
- Use `node:` prefix for built-in modules
- Write lowercase comments sparingly
- Avoid `export default` in routes (use named exports)

### Performance

- Use `useStableMemo` to prevent unnecessary re-renders
- Lazy load heavy components
- Use FlashList for long lists
- Optimize images before uploading

### Testing

- Write tests for critical business logic
- Test error states and edge cases
- Mock external dependencies
- Use factories for test data

### Security

- Never commit secrets to `.env.development`
- Use environment variables for sensitive config
- Validate user input on server and client
- Sanitize database queries (Drizzle does this automatically)
