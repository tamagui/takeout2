KEY FACTS ABOUT @vxrn/mdx
================================================================================

VERSION: 1.2.7
TYPE: CommonJS (requires dynamic import in ESM)
USE CASE: Complete MDX processing with bundling, highlighting, and metadata

MAIN FUNCTIONS:
  1. getMDX(source) → bundles MDX string
  2. getMDXBySlug(path, slug) → loads & bundles MDX file
  3. getAllFrontmatter(path) → extracts all metadata from directory
  4. getAllVersionsFromPath(path) → lists semantic versions
  5. createCodeHighlighter() → standalone syntax highlighting

CORE FEATURES:
  ✓ MDX bundling with mdx-bundler
  ✓ YAML frontmatter parsing with gray-matter
  ✓ Syntax highlighting with Prism/refractor
  ✓ Line highlighting (via meta attributes)
  ✓ Word highlighting (via __underscores__)
  ✓ Heading extraction & TOC generation
  ✓ Reading time calculation
  ✓ Version management for components
  ✓ Customizable rehype plugin pipeline
  ✓ Auto-slug generation

KEY DEPENDENCIES:
  - mdx-bundler v10.0.2 (core MDX processing)
  - gray-matter v4.0.3 (frontmatter parsing)
  - refractor v4.7.0 (Prism-based highlighting)
  - reading-time v1.3.0 (reading time)
  - rehype ecosystem (HTML transformation)
  - fast-glob v3.3.3 (file scanning)

IMPORTANT CONSTRAINTS:
  ✗ Node.js only (not browser)
  ✗ CommonJS module (ESM requires dynamic import)
  ✗ mdx-bundler is async (must await)
  ✗ Output code must be evaluated with mdx-bundler/evaluate()
  ✗ Code highlighting is post-processing (not in HTML AST)
  ✗ Limited to registered refractor languages (TSX, CSS by default)

================================================================================
EXPORTED API SUMMARY
================================================================================

getMDX(source: string, extraPlugins?: UnifiedPlugin)
  INPUT:  MDX content as string (with YAML frontmatter)
  OUTPUT: { frontmatter: Frontmatter, code: string }
  ASYNC:  Yes
  USES:   mdx-bundler, gray-matter, refractor

getMDXBySlug(basePath: string, slug: string, extraPlugins?: UnifiedPlugin)
  INPUT:  Directory path, file slug (without .mdx)
  OUTPUT: { frontmatter: Frontmatter, code: string }
  ASYNC:  Yes
  SMART:  Auto-detects latest version for components
  USES:   fs.readFileSync(), getMDX()

getAllFrontmatter(fromPath: string)
  INPUT:  Directory to scan
  OUTPUT: Frontmatter[] (sorted by publishedAt descending)
  ASYNC:  No (synchronous)
  USES:   fast-glob, gray-matter, getHeadings()

getAllVersionsFromPath(fromPath: string)
  INPUT:  Directory path
  OUTPUT: string[] (semantic versions, descending order)
  ASYNC:  No (synchronous)
  USES:   fs.readdirSync(), compare-versions

createCodeHighlighter()
  INPUT:  None (returns function)
  OUTPUT: (source, lang, line?) => string (HTML)
  ASYNC:  No (synchronous, singleton)
  USES:   refractor, rehypeHighlightLine, rehypeHighlightWord

================================================================================
FRONTMATTER STRUCTURE
================================================================================

REQUIRED FIELDS:
  title: string           (your page title)
  slug: string            (for URL & identification)

OPTIONAL METADATA:
  description: string     (SEO, preview)
  publishedAt: string     (ISO date, used for sorting)
  draft: boolean          (hide unpublished posts)
  by: string              (author name)
  image: string           (preview/og image)
  poster: string          (cover image)
  type: string            (changelog, article, etc.)
  
COMPONENT-SPECIFIC:
  component: string       (component name)
  package: string         (npm package name)
  demoName: string        (demo identifier)
  
VERSIONING:
  version: string         (current version)
  versions: string[]      (available versions)
  relatedIds: string[]    (related content)

AUTO-GENERATED (by getMDX/getAllFrontmatter):
  headings: { title, priority: 1-6, id }[]
  readingTime: { text, minutes, time, words }

================================================================================
PERFORMANCE NOTES
================================================================================

ASYNC OPERATIONS (can be slow):
  getMDX()         - Depends on bundling (can be 100ms+)
  getMDXBySlug()   - I/O + bundling
  
SYNC OPERATIONS (fast):
  getAllFrontmatter()      - O(n) file reads (cache it!)
  getAllVersionsFromPath() - O(n) directory read
  createCodeHighlighter()  - Singleton (first call slowest)

RECOMMENDATIONS:
  1. Cache getAllFrontmatter() results (expensive for many files)
  2. Lazy load MDX bundles (don't process all at once)
  3. Use static generation for known routes
  4. Consider build-time preprocessing for frequently accessed content
  5. Evaluate code only when rendering (not at server start)
