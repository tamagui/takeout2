Zero is a sync engine that brings your backend data to the client. Queries run locally against a persistent cache, mutations apply instantly, and everything syncs in the background. The result: apps that feel as fast as native desktop software.

## Why Zero

Traditional apps make network requests for every interaction. Zero inverts this: data lives on the client, queries execute locally, and sync happens automatically. Your UI updates in the next frame, not after a loading spinner.

- **Instant interactions** - Zero latency for cached data
- **Real-time sync** - Changes propagate to all clients automatically
- **Offline support** - Full functionality without network
- **Simpler code** - No loading states, no request management

## How It Works

Zero sits between your UI and database, maintaining a client-side replica:

```
┌─────────┐    ┌──────┐    ┌──────────┐
│   UI    │◄──►│ Zero │◄──►│ Postgres │
└─────────┘    └──────┘    └──────────┘
                  │
              local cache
              (IndexedDB)
```

Queries run against the local cache. When data isn't cached, Zero fetches it on demand. Mutations apply optimistically on the client, then sync to the server.

## Key Features

### Reactive Queries

Queries update automatically when data changes:

```tsx
import { useQuery } from '@rocicorp/zero/react'

function PostList() {
  const posts = useQuery(z.query.post.orderBy('createdAt', 'desc'))

  return posts.map(post => <PostCard key={post.id} post={post} />)
}
```

No refetching, no cache invalidation. Change a post anywhere and every query that includes it updates.

### Optimistic Mutations

Mutations apply instantly on the client:

```tsx
async function likePost(postId: string) {
  await z.mutate.postLike.insert({
    id: createId(),
    postId,
    userId: currentUser.id,
  })
}
```

The UI updates immediately. Zero syncs to the server in the background and handles conflicts automatically.

### Server Permissions

Authorization runs on the server, transparent to the client:

```ts
// schema.ts
const postPermissions = {
  row: {
    select: (post, ctx) => post.published || post.authorId === ctx.userId,
    update: (post, ctx) => post.authorId === ctx.userId,
    delete: (post, ctx) => post.authorId === ctx.userId,
  }
}
```

Clients query freely. The server enforces what they can actually see.

### Platform Storage

Zero adapts to each platform:

- **Web** - IndexedDB for persistent cache
- **Native** - SQLite for better performance
- **Anonymous** - In-memory for unauthenticated users

## Takeout Integration

Takeout pre-configures Zero with:

- **Schema generation** - Define tables in Drizzle, Zero types generate automatically
- **Auth integration** - Better Auth tokens work with Zero permissions
- **Three-database setup** - Upstream, CVR, and change databases configured
- **Global query builder** - Access `zql` anywhere without prop drilling

## Basic Usage

```tsx
// query posts with related data
const posts = useQuery(
  z.query.post
    .related('author')
    .related('comments', q => q.limit(5))
    .where('published', true)
    .orderBy('createdAt', 'desc')
    .limit(20)
)

// mutate with full type safety
await z.mutate.post.update({
  id: postId,
  title: 'Updated Title',
})
```
